# Important Memories

## Vision Development

Vision is being rebuilt carefully after lessons from earlier projects.

The current project intentionally follows a staged implementation
process.

## Vision Body First

The current development strategy is to build the application body
before connecting the full AI engine.

## Current Vision Structure

Primary experiences:

- Chat
- Code
- Projects
- Models
- Terminal
- Plugins
- Settings

## Chat

Chat is intended to provide the normal premium AI assistant experience.

## Code

Code is intended to be a Claude Code-style AI coding workspace.

It is not intended to become a full traditional IDE.

## Terminal

Vision will eventually contain a real Windows terminal for:

- PowerShell
- CMD
- development
- model/runtime management
- future agent workflows

## Models

Vision should eventually allow models to be discovered and configured
from different sources.

## API Testing

Initial Vision development may use API-based models before local models
are installed.

## Local AI

Ollama is the first planned local runtime, but Vision must remain
runtime-independent.

## Agents

A lightweight Hermes-based agent may be used first to test the future
agent architecture.

Stronger coding models such as DeepSeek and Qwen may be used later.

## Plugins

Potential integrations include:

- Obsidian
- Blender
- memory systems
- Ponytail
- other external services

## Vision Orb

The Vision Orb is an important part of the product's visual identity.

Its implementation is based on mature Three.js techniques and should
remain isolated from model logic.

## Current External Knowledge System

Obsidian is currently being prepared independently and is not yet
connected to Vision.
