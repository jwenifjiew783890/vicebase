# Vision Project

## Purpose

Vision is a local-first AI platform designed to provide a unified
experience for conversation, coding, models, agents, tools, projects,
terminal workflows, and future integrations.

## Primary Experiences

### Chat

A premium Claude-like conversational experience.

Future capabilities include:

- conversations
- model selection
- files
- attachments
- images
- image generation
- markdown
- code
- streaming
- tools
- agents

### Code

A Claude Code-style AI coding workspace.

The goal is for an AI coding agent to work on real local projects.

Future capabilities include:

- project inspection
- file reading
- file creation
- file modification
- terminal commands
- testing
- debugging
- iteration
- diffs
- permissions

### Terminal

A real Windows terminal inside Vision.

Eventually used for:

- development
- runtime installation
- local model installation
- model management
- agent workflows

### Models

Vision should support multiple model providers and runtimes.

Examples:

- Ollama
- llama.cpp
- vLLM
- LM Studio
- API providers
- custom compatible endpoints

Models must be dynamically configurable/discoverable.

### Agents

Agents are future workers that operate through controlled
capabilities.

Potential roles:

- coding
- planning
- research
- debugging
- testing
- automation

Agents should not be hardcoded into Vision Core.

### Plugins

Optional external capabilities should be isolated through plugins.

Examples:

- Obsidian
- Blender
- memory systems
- Ponytail
- future integrations

### Vision Orb

The Orb is part of Vision's visual identity and should remain isolated
from model/provider logic.

## Core Principle

Vision Core = stable platform.

Models = interchangeable intelligence.

Agents = interchangeable workers.

Plugins = optional extensions.

Obsidian = external knowledge/memory.

Terminal = environment control.
